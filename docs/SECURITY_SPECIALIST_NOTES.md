# 情報処理安全確保支援士 (SC) 学習ノート

本ドキュメントは、情報処理安全確保支援士試験（登録セキスペ）の午後問題（記述・事例解析）および午前IIのセキュリティ専門知識に直結する技術的着眼点を整理したものです。

---

## 1. 認証・セッション管理 (午後試験 最頻出テーマ)

### Cookie属性の組み合わせと防護対象
| 属性 | 防護対象の脅威 | SC試験での解答キーワード |
| :--- | :--- | :--- |
| `HttpOnly` | XSSによるセッションID窃取 | 「スクリプトからのCookie読み出し禁止」「被害の極小化」 |
| `Secure` | 通信経路上での盗聴・平文送信 | 「HTTPS通信時のみCookie送信」「盗聴の防止」 |
| `SameSite` (`Lax`/`Strict`) | クロスサイトリクエストフォージェリ (CSRF) | 「クロスサイトリクエスト時のCookie送出制限」 |

> **試験対策ポイント**:
> - 「XSS脆弱性を完全に排除できない前提において、セッションハイジャックのリスクを低減させる対策は何か？」という問いに対して、`HttpOnly` 属性の付与を即答できることが求められます。
> - `SameSite=Lax` はトップレベルナビゲーション（リンククリック等）におけるGETリクエストではCookieが送信されるため、状態変更（更新・削除）をGETで実装してはならない原則（HTTPメソッドの適切な使い分け）とセットで出題されます。

## 2. アクセス制御・認可制御 (Broken Access Control)

### 不備のメカニズムと対策
1. **問題の本質**:
   - 画面遷移（リンクやボタン）の非表示だけに頼り、リクエストURL直接指定やパラメータ改ざん時のサーバー側権限判定を怠る。
2. **試験での着眼点**:
   - リクエストを受け取ったサーバー側コントローラにおいて、セッションから復元したログインユーザーの識別子およびロールが、対象リソースの所有者または実行可能権限と一致するかを**必ずすべてのエンドポイントで**照合すること。

---

## 3. レスポンスヘッダーによるブラウザ防御 (Defense in Depth)

### 代表的なヘッダーとその目的
1. **`Content-Security-Policy` (CSP)**:
   - ブラウザが読み込み・実行を許可するリソース（スクリプト、スタイル、画像等）のオリジンをホワイトリスト形式で指定。
   - インラインスクリプトの実行抑止や、意図しない外部ドメインへの接続遮断。
2. **`X-Content-Type-Options: nosniff`**:
   - ブラウザによるContent-TypeのMIMEスニッフィングを無効化。
   - 画像等の非実行可能ファイルとしてアップロードされた悪意あるスクリプトの実行を防止。
3. **`HSTS` (HTTP Strict Transport Security)**:
   - 初回アクセス以降、ブラウザに対して強制的にHTTPS接続を行わせるヘッダー（`Strict-Transport-Security: max-age=...; includeSubDomains`）。
   - SSL/TLS Strip攻撃の防止。

## 4. ログ取得とインシデント検知 (NIST SP 800-92 / JIS Q 27001)

### 監査ログに必要な4要素
1. **When（いつ）**: NTP等で高精度に同期されたタイムスタンプ（UTC推奨）
2. **Where（どこで/どこから）**: アクセス元IPアドレス、対象エンドポイント
3. **Who（だれが）**: アカウント識別子（ログイン試行されたユーザー名）
4. **What（なにを）**: 実行結果（`AUTH_SUCCESS` / `AUTH_FAILURE`）

> **禁止事項 (試験でも問われる規律)**:
> - ログに平文パスワード、クレジットカード番号、認証トークン等を出力してはならない（過剰記録による漏洩リスク）。
