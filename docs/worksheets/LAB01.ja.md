# LAB-01 ワークシート: 認証と認可の違い

[English](LAB01.md) | [日本語](LAB01.ja.md)

ローカルで行う、合成データだけの演習です。自分のマシン上のラボアプリと、固定の演習アカウント `alice` / `user`、`admin` / `admin` だけを使ってください。このワークシートに答えは載っていません。自分の答えを書いた後で、別ファイルの[解答](../solutions/LAB01.ja.md)を読んでください。完了は形成的な練習であり、能力を保証する検証済み証明ではなく、独力でコードを書ける力を示すものでもありません。

このワークシートと回答は、ローカルの学習記録として保管します。スキャン成果物には添付せず、Cookie の値、セッショントークン、実在の個人情報はどこにも貼らないでください。

## W1. 範囲と準備

アプリを `127.0.0.1` で起動します([実習ガイド](../LAB_GUIDE.md)参照)。`/health` を開き、報告された `mode` を書き留めます。対象がローカルアドレスだけであることを確認します。

## W2. 実行前に予測する

観察の前に、各モードで各アクターが `/admin` を要求したときの結果を記入します。ステータスコードと、リダイレクトする場合はその行き先を書いてください。

| `/admin` を要求するアクター | VULNERABLE(あなたの予測) | HARDENED(あなたの予測) |
| --- | --- | --- |
| 未認証 | | |
| `alice`(ロール `user`) | | |
| `admin`(ロール `admin`) | | |
| ログアウト後に自分のセッショントークンを再利用した `alice` | | |

## W3. 観察する

VULNERABLE のアプリに対してスキャナーを実行し、LAB-01 のチェックだけを読みます。

```bash
security-lab scan http://127.0.0.1:8000 --format json --expected-mode VULNERABLE
```

LAB-01 の無害化済み `observations`(actor、endpoint、status、redirect)を写し、チェックの status と `reason_code` を記録します。W2 の予測と合ったか、合わなかった点はどこかを書きます。

## W4. 原因を説明する

1. 認証と認可の違いを、自分の言葉で説明してください。
2. 利用者が誰かを示したリクエストはどれで、欠けていた判断は何ですか。
3. ロールの判断を置くべきファイルと関数を挙げてください。

## W5. 修正方針を選び、理由を述べる

方針を1つ選び、理由を説明します。正当な管理者の利用が引き続き動く理由も含めてください。

- A. 管理者でない利用者には、ページ上の管理画面リンクを隠す。
- B. 管理画面を返す前に、サーバー側でログイン中ユーザーのロールを確認し、満たさなければ拒否する。
- C. ブラウザの JavaScript でロールを確認する。
- D. 要求元のネットワークアドレスで管理画面を制限する。

## W6. 再検証

W2 のアクターを、修正後または HARDENED のアプリに対して繰り返します。拒否されるケース、許可される管理者のケース、ログアウト後のトークンのケースを記録します。ログアウト後のトークンが失敗しなければならない理由を説明してください。

## W7. 限界

このチェックでは確認できないことを、少なくとも1つ書きます。他のルート、オブジェクト単位の権限、検出0件の意味、HTTP クライアントでは見えないことを考えてください。

## W8. 応用(紙上のみ)

新しく考えた架空のルート `GET /reports/{id}` が、特定の利用者に属するレポートを返します。コードを書いたり実行したりせずに、サーバーが行うべき確認、テストマトリクスに入れる内容、そのテストでもなお確認できないこと1つを挙げてください。

## 任意のヒント

行き詰まったときだけ、順番に使います。使った最大のヒントレベルを記録してください。

- [H1] 本人であることと、許可されていることは別です。
- [H2] 管理画面のハンドラーを調べます。
- [H3] 未認証・一般ユーザー・管理者を確認し、正当な利用も確認します。

## 形成的ルーブリック

各軸を 0(なし・誤り)、1(一部根拠あり)、2(正しく、記録した証拠で裏付けられている)で採点します。合格の閾値はありません。ヒントレベルと所要時間は別に記録し、スキャン結果は学習の得点にしません。

| ID | 軸 | 問い | 証拠の基準 |
| --- | --- | --- | --- |
| R-POLICY | 方針 | 誰に許可すべきか、その理由は何か | W2 の表が、許可・拒否するアクターを理由付きで示し、正当な管理者の利用を含む |
| R-MECHANISM | 仕組み | 原因は何で、修正はなぜそれに対処するのか | W4/W5 が欠けていた判断と、それを置く場所を示す |
| R-VERIFICATION | 検証 | 拒否と正当な成功をどう示したか | W3/W6 が、未認証・一般ユーザー・管理者・ログアウト後トークンの無害化済みステータスを引用する |
| R-LIMITATIONS | 限界 | 何が示せていないか | W7/W8 が残る限界を述べ、方針を紙上のシナリオに適用する |
